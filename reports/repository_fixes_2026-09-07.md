修复过程中还补齐了两处同链路问题：上传处理器原先读取错误的 `manifest.run_id`，现在优先读取实际的 `manifest.run.run_id`，避免成功上传仍丢失历史引用；OpenAI 客户端现在把额外请求头实际传入 SDK 的 `default_headers`，并通过真实工厂函数与模拟 SDK 构造验证。

发布流程现为：本地准备版本 → 构建与签名 → 校验产物及 SHA-256 → 原子推送分支和标签 → 上传发行资产。自动和手动发布共用互斥组。使用临时本地 Git 远程实际验证：产物缺失、内容被改动、空文件或标签冲突均不推进 main；验证通过后分支和标签一起更新。Git 引用发布与 GitHub 资产上传是两个独立操作；资产上传失败时可通过现有标签重新运行手动发布。
